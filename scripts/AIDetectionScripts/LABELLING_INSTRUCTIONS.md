# AI-disclosure labelling

## What you're doing

My regex flagged these commits because their message mentions something that
might indicate AI use. Most are false positives, the literature reports
only 30–47% precision for this kind of keyword search.
Your job is to decide, for each row, whether the commit message says
an AI tool was involved in **writing this change**.

We will compute inter-rater agreement (Cohen's κ) from
 two independent passes (mine and whoever else does it). Disagreements get resolved afterwards by a third person.

## Columns

| Column | What it is |
|---|---|
| `row_id` | Unique ID. Don't change it.|
| `window` | Which dataset the commit belongs to (human window or AI window)|
| `date`, `author` | Commit date and author email |
| `component` | Bugzilla product :: component |
| `matched` | Which regex term fired |
| `context` | The actual line(s) from the commit message that matched **ADDED SCRIPT** show commit.py to get the full message if 120 isnt enough, just use ID from above|
| `subject` | Commit subject line |
| **`label`** | **You fill this in** |
| `notes` | Optional, anything you were unsure about, might help with decision making later|


## Labels

Use exactly these strings.

| Label | Meaning |
|---|---|
| `AI_DISCLOSED` | The message says an AI tool wrote or helped write this change |
| `AI_BORDERLINE` | AI was used only to review, analyse, or explain, but a human wrote the code |
| `FP_FEATURE` | The change is to Firefox's own AI features (chatbot sidebar, ML code, Gemini Nano). The tool is the *subject*, not the author. |
| `FP_TOOLING` | The change is to AI dev tooling. `CLAUDE.md`, `AGENTS.md`, `.cursor/` configs, agent instructions |
| `FP_NOISE` | Match is a non-AI generator (clang-tidy, ffmpeg, mach, bindgen), "cursor" as a UI element, a person named Devin or Claude, or "AI" in ordinary prose |
| `FP_OTHER` | A false positive that doesn't fit the above, explain in `notes` |
| `UNSURE` | You genuinely cannot tell. Use sparingly. |

## The distinction that matters most

**Who wrote the code**, not what the code is about.
Examples:
- `Bug 123: Add Copilot to list of chatbot providers` **FP_FEATURE**.
  Firefox is adding a feature. No AI wrote this patch.
- `Bug 456: Fix parser crash. Generated using Claude on the CLI.` 
  **AI_DISCLOSED**. The author says an agent produced the change.
- `Bug 789: Add component mapping for AGENTS.md and CLAUDE.md` →
  **FP_TOOLING**. Configuration for agents, not written by one.
- `Bug 321: Fix cursor position in text field.` **FP_NOISE**. Text cursor, not AI cursor.
- `Bug 654: Update generated bindings. Generated by bindgen.` **FP_NOISE**.

- **Co-authored-by an agent IS disclosure** — `Co-authored-by: Claude
  <noreply@anthropic.com>` is the strongest signal there is.
- **Borderline vs disclosed:** "used Claude to review this patch" is
  `AI_BORDERLINE`, "Claude wrote the test cases" is `AI_DISCLOSED`. If the
  message says the tool produced code that landed, it's disclosed.
- **When torn between two false-positive categories**, pick either — all FP
  labels are collapsed to "not AI" in the analysis. Don't stress.
